# 时间回溯树内核文档

本文档提供时间回溯树的后端逻辑的概述与实现语义。前端导航逻辑（当前点、焦点链、尝试、关键点、显示与交互规范）见[时间回溯树 UI 文档](undo-tree-ui-document.md)，两文档互补，本文档只约束内核。

> [!NOTE]
>
> **实现状态**：操作日志、时间回溯树（f(日志) 派生）、统一撤销（三形态 + 截断）、重做（重做栈 = 派生投影）、三级容器模型（增量式分子归并、超分子即时物化与聚合折叠、discard 型取消选择）、commit 边界单管线、远端应用入口（「插入与重放的边界」分流 + 全量重建兜底 + 白板链过渡）、日志与 trash 持久化及跨会话撤销（见[会话存储内核文档](../../store/docs/store-document.md)）均已落地（`src/kernel/hit/`、`src/kernel/api/`、`src/kernel/store/`）；九个情景推演已固化为回归测试。同步传输（延迟容忍窗、AOM 活动事件复制、amend 通道）亦已落地，见[同步层文档](../../../host/sync/docs/sync-document.md)。待落地项见各节 [todo] 标记。

## 单一共享树

内核内有且仅有一份操作日志与一棵 hit 树：所有用户的操作都记录在这份日志中，树是日志的追溯结构。

- **操作为王**：操作是一等公民，携带 id、author、时间标记与内容，可产生多个节点（分子操作、超分子操作的固有性质）。操作与树分离——移动指针类等操作不产生节点，也记录在日志中。
- 节点的数据不由节点自己持有，而是放在数据池中凭 share id 获取；多个节点可凭同一 share id 共享数据（如撤销改挂的两侧），全部操作可溯源。
- 树天然保留分支：撤销后产生的新操作长成新分支，旧分支保持原状。各端的分歧是尚未收到的操作，补齐后即为同一份日志与同一棵树，不涉及多棵树的合并。
- 内核维护共享的 HEAD 指针。HEAD 指向当前状态对应的节点，其更改记录为分子操作并同步；按「所有用户一致」原则，网络同步良好时各用户的 HEAD 与 hit 相同。后继点、焦点链、尝试等派生自导航的概念属于前端状态，见前端文档。

## id 命名空间

对象与操作的 id 是来源命名空间的字符串：`"{source}/{n}"`（空来源为 `"{n}"`）。内核自动创建的对象（如擦除分裂段）使用子命名空间 `"{source}/core/{n}"`（空来源为 `"core/{n}"`）。

- source 即协作身份，也是 hit 节点的 author；来源前缀保证各端并发分配互不冲突，无需跨端协调。
- id 计数器将写入白板文件 meta，加载时恢复，保证保存重开后不重复发号；多用户共享白板时，各用户在自己的 source 下独立计数。
- 节点的 share id 取自操作 id 命名空间，不是独立发号：独立节点为唯一成员记录 id，分子节点为首成员记录 id，聚合节点为段首成员记录 id（恒等于 memberIds 首元素；仅 K1.5 旧形态节点取超分子锚记录 id）。改挂产生的节点副本共享同一 share id，撤销记录的 targetNodeId/previousHeadId 与记录的 parentId 都按它解析——它是落盘与跨端的逻辑身份。节点没有也不需要有副本级「树节点 id」：副本是各端本地构建的追溯结构，跨端与落盘都无法解析，内存中又以对象引用直达。

## 节点与操作

内核维护的节点模型：父链与子节点、深度、所属操作——树状结构记在节点上。节点不存时间（时间随所属操作），数据不自带，放在数据池中凭 share id 获取。一个操作可产生多个节点（分子操作、超分子操作）；移动指针类操作只有日志记录，不产生节点。当前点、后继点、尝试（attempt）与收树派生自用户导航，属于前端状态；`AttemptNode` 是前端为展示与导航维护的结构，内核不维护。

节点携带一个分子操作（`MolecularOperation`），操作模型见[操作文档](operation-document.md)：

- 操作记录类型：增加对象、修改对象、删除对象、选择对象、取消选择对象、更改 HEAD 指针、撤销、重做，以及闭合超分子记录（close-supra，自身不产生节点，触发聚合折叠）；多个分子操作可有序合成超分子操作（如一次「选择 → 修改 → 提交」会话）。
- 增加与修改对象额外记录操作时刻的完整层栈快照（z-order）；删除对象将对象移入 trash（板根 `trash/`，布局 v1），经 hit 可找回；删除记录自身携带对象快照与层位边，各端凭记录重建 trash 条目。
- 原子操作（拖拽中间帧、书写采样点）发生在 AOM 动态图中，不产生节点、永不落盘；进行中经 amend 通道向远端 volatile 广播（只画不存），endMol 时凝聚为分子记录追加到树上。
- 节点形态（三级容器归并）：独立分子节点为单记录；增量式分子（beginMol → amendMol → endMol/abortMol 承载一次手势）物化时每对象一条记录、同 molId，同 molId 且同 supraId 的相邻记录归并为一个分子节点（被并发操作分隔时各自独立成节点，退化但语义安全）；abortMol 丢弃 amend 流不留痕。
- 超分子（supra key）：一次「选择 → 修改 → 提交」会话以 `beginSupra(key)` 开启、`endSupra(key)` 闭合（`abortSupra(key)` 异常中止，撤销全部活跃成员）；成员提交即时物化上链（记录携带 supraId），不缓冲草稿，未指定 key 的提交永远独立成录。endSupra 在成员记录不少于 2 条时追加 close-supra 记录，树构建把活动链上同 supraId 的连续节点段折叠为聚合节点——段内不少于 2 节点才折叠，已撤销分支成员不参与，成员被并发异节点分隔时逐段折叠（退化）；撤销粒度随折叠从分子级升到聚合节点级。
- 操作携带时间标记（物理时间 + author 决胜），是操作日志排序与状态回放的依据；节点不携带时间。

## 树的生长

1. commit 在 HEAD 所指节点之后追加节点。增量式分子的相邻记录（同 molId 且同 supraId）并入活动链末端节点——一个分子始终是链上一个节点；乱序到达或被并发操作分隔时各自独立成节点（退化，语义安全）。闭合超分子记录（close-supra）不产生节点：活动链上同 supraId 的连续节点段逐段折叠为聚合节点（段内不少于 2 节点才折叠；已撤销分支上的成员不参与；段内节点携带的分支子节点转挂聚合节点，重做目标不丢；HEAD 落在段内时移到聚合节点）。
2. 延迟到达的增加节点按 (时间, author) 插入活动链的对应位置，插入点之后的节点改挂；延迟造成的分叉不允许保留——分叉只能来自用户的显式意图（撤消），不能来自同步的偶然（「所有用户一致」原则，见[情景推演](undo-tree-kernel-example.md)情景二）。父节点记录是创建时的本地视图：父不在活动链上时（如父已被撤销），节点仍按时间插入活动链（见[情景推演](undo-tree-kernel-example.md)情景八）。
3. 撤销记录目标节点 D（缺省为本端来源最近的活动链节点，各撤各的）：在 D 的父节点处分叉，D 与 HEAD 之间的链（不含 D）改挂到分叉点，原位置保留的子树按 (时间, author) 截断——不晚于撤销操作的节点留在原位置（凭同一 share id 共享数据），晚于的只存在于撤消分支；HEAD 移到新末端。D 为活动链末端时退化为 HEAD 回退；D 不在活动链上时被吸收。改挂是到达节点正确落位的前提：后续按父亲 id 到达的节点只有在活动链上找到原节点身份，才能挂到正确位置。逻辑上树只增不改，操作级 CRDT 不被破坏——增量式分子归并就地向活动链末端节点追加 memberIds、折叠以聚合节点在段首位置就地替换段（undo-tree-core.js），都是派生结构的重整，不改变操作级只增不改的语义。
4. 重做把 HEAD 移到最近一次生效撤销记录的原 HEAD 位置，是纯 HEAD 移动；被吸收（未生效）的撤销不产生重做目标。
5. 撤销后的新操作在 HEAD 所指位置追加子节点，原分支保留。
6. HEAD 指向当前状态对应的节点，可在链中间：root→HEAD 是活动链，HEAD 下游的后代是已撤销的节点（可重做）。HEAD 随结构变更自然移动，由日志派生、不参与仲裁：HEAD 移动操作按日志序回放、条件应用——仅当评估时 HEAD 恰为操作起点才移动指针（见[时间回溯树内核情景推演](undo-tree-kernel-example.md)情景三）。
7. 删除的对象进入 trash（板根 `trash/`），经 hit 可找回。

## 协作语义

### 操作级 CRDT

hit 节点的粒度只有分子操作与超分子操作两种，合称节点粒度。操作携带时间标记，接收方无论以什么顺序接收操作，都能重建出同一份日志与同一棵树：日志由 (时间, author) 唯一排序，树由操作的结构效果按序应用唯一确定。断线期间产生的操作在重连后按同样规则并入，各端自然一致。

### 「所有用户一致」原则

也称「所用在一」，即网络同步良好时，所有用户的 HEAD 指针相同，每个用户的 hit 也相同。因此不存在分支合并：分歧只是尚未收到的节点，补齐后各端的树与 HEAD 自然一致。

「所有用户一致」要求多用户的树与单一用户按时间顺序操作的结果一致：分叉只能来自用户的显式意图（撤消），不能来自同步的偶然（延迟）。因此延迟到达的增加节点按 (时间, author) 插入活动链的对应位置（插入规则）；创建时记录的父节点是创建者的本地视图，建树以时间序为准。

### 状态收敛

树收敛后，当前状态由根到 HEAD 的节点序确定性回放得到，冲突语义内建于回放：

- **同一对象的同一属性** — 后到的节点覆盖先到的（Last Write Win）。
- **同一对象的不相交属性** — 各节点的修改都保留（按 properties 集合分别应用快照）。
- **对象的层位（z-order）** — 由节点序决定，后到的增加对象居上；节点记录的层栈快照只用于撤销与层位修复。

回放对所有端一致，状态由回放唯一确定，无需独立仲裁——确定性来自树构建规则（时间标记 + author 决胜）与回放规则本身。

### 增量维护与层位修复

各端可以增量维护当前状态而不必每次从头回放，以下确定性规则保证增量路径与回放一致：

- **快照缓存原则** — 节点快照仅作增量维护的缓存；撤销后的分支状态以分支点重放为准，重放链长为目标节点到 HEAD 的距离。复制节点时按被撤操作修补快照是可选优化，不改变语义。
- **回放是真相** — 旧操作插入改变上下文敏感操作（如撤销）的应用环境时，受影响的后缀按日志序重放重估；撤销的退化 / 分叉形态在应用时确定，可随上下文变化，最终树只由日志决定。
- **插入与重放的边界** — 按日志序，根据到达操作的类型与其插入点之后的已应用操作判定：增加节点类与撤销在插入点之后只有增加节点类时纯插入 / 纯应用（截断保证殊途同归）；插入点之后存在任何非增加节点类记录（撤销、重做、更改 HEAD 指针、close-supra）时后缀重放；close-supra（折叠类）同属上下文敏感，作为到达记录按同表分流——插入点之后只有增加节点类时纯应用，否则后缀重放；重做与更改 HEAD 指针在插入点之后有任何已应用操作时一律后缀重放——其条件应用引用 g(日志前缀)，任何后续操作都会改变求值环境。同步良好时重放是异常路径；延迟容忍窗把乱序攒批整理，降低重放频率（见「延迟容忍窗」；推演见[时间回溯树内核情景推演](undo-tree-kernel-example.md)「插入与重放的边界」）。
- **层位缝合规则** — 回退删除或层位修改时，按节点记录的层栈快照插回：快照内仍存在的成员按快照相对位置定位；快照中不存在的层（快照之后创建）按时间序判定上下，后到者居上。

### 延迟容忍窗

同步延迟造成乱序到达：乱序节点按插入规则落位会引起级联改挂，落在上下文敏感操作之前的还会触发后缀重放（见「增量维护与层位修复」）。延迟容忍窗吸收这种抖动：窗内到达的乱序操作先到先挂，窗口到期一次性按 (时间, author) 整理——插入规则落位 + 必要的后缀重放。

- **语义保证**：整理后的结果与逐条按日志序应用相同——树 = f(日志)，窗口只改变中间过程的抖动次数，不改变最终结构。
- **工程收益**：把窗口内的多次改挂与重放合并为一次整理；同步良好时整理为空转。
- **机制细节**：窗长 500ms；序号空洞（来源操作序号不连续）或父记录未达的乱序记录先入缓冲并触发开窗，窗口到期按 (时间, author) 一次性整理——可接入分组逐轮排空（插入规则落位 + 必要的后缀重放）；连续 3 窗未补齐则广播 request-init 请求全量（实现见 `host/sync/network-coordinator`，语义见[同步层文档](../../../host/sync/docs/sync-document.md)）。

### 时间标记

节点以物理时间为第一关键字排序，同一时刻按 author 字典序决胜，给出确定性的全序。不要求严格的时钟同步：物理时间的漂移只影响并发节点的先后判定，不影响因果顺序（父亲必先于子节点存在）。入房时可校准成员的时间偏移以收窄漂移（可选优化）。节点的创建时间同时用于界面展示。

### AOM 活动状态

pickup（选择对象）与 commit（取消选择、提交）作为事件经可靠通道同步：远程活动对象在各端的 AOM 中可见（层级结构一致）但锁定——不可编辑、不可擦除，与「活动对象不可擦除」的互斥规则一致。手势的中间帧经 amend 通道（volatile）广播：begin-mol 即时发出（create 型带创建快照），amend 按 33ms 节流合批（position 等绝对值后帧盖前帧、append 保序、带 seq），end-mol / abort-mol 收尾；只画不存、丢失不补，最终的分子记录经可靠通道到达时定格归位。断线重连以未闭合分子清单（openMols）对账重放缺失段（见[同步层文档](../../../host/sync/docs/sync-document.md)）。

### 传输与兜底

- **可靠通道** — 分子 / 超分子操作记录（含 close-supra）与 AOM 活动事件的广播已落地；HEAD 更改（move-head）尚无生产端与应用入口（树应用对 move-head 记录抛错），待落地。[todo]
- **不可靠通道** — amend 通道（分子中间帧预览：begin-mol / amend / end-mol / abort-mol，33ms 合批、只画不存）、光标等 awareness（volatile：可丢、不进日志）。
- **定期状态摘要（digest）兜底** — 30s 周期互换 `{logSize, head, objects, stateHash, openMols}`，修补丢包造成的分歧：对端 logSize 领先或同长而 head 分歧时请求全量；stateHash 分歧（日志逐字节一致但效果未放全）经 `repairStateFromLog` 本地重放自愈——f(日志) 确定，重放即得正确状态；任一端 openMols > 0（有未闭合分子，活体合法偏离派生态）时跳过本轮比对。
- **新用户加入** — INIT 握手（request-init / respond-init）：携带 lastSeen 摘要（本端各来源最大操作序号）时按缺口增量回应，无 lastSeen 时全量回应；容忍窗连续超窗未补齐自动转全量。超时回退持久化存储拉取待实现。[todo]

### 同步边界

本设计不提供采样点级 CRDT：活跃手势期间（AOM 动态图，不产生节点）各端的对象层级视图以本地为准，可能短暂不一致；commit 后节点按序收敛。语义接近「Local & Last Write Win」。

### 协作撤销

HEAD 为所有用户共享，撤销与重做对各用户可见。谁能撤销什么（可否撤消他人的操作）是 UI 层的交互策略；内核提供统一的机制：撤销（记录目标节点，应用时按目标在活动链上的位置呈现退化或分叉形态）与重做（见[操作文档](operation-document.md)）。撤销记录目标节点：离线撤销在合并时按合并树上的目标位置应用，意图被保留。被撤消的操作与其分支始终留在树上。

撤销粒度随三级容器模型：未闭合超分子的成员按分子级撤销（undo 缺省目标为本端来源最近的活动链节点）；闭合后的聚合节点作为整体成为撤销目标（commit 与 discard 型闭合殊途同归——回选择前并取消选择）。撤销发生时本端未闭合的增量式分子先强制 endMol 物化再撤（`BoardApi.undo` 返回 `forcedEndMolIds`），保证所有效果都有记录可撤。

## 存储

树的日志段与 trash 随布局 v1 落盘：板根下 `board.json`、`objects/`、`trash/`、`chunks/`、`hit/seg-*.jsonl`，无 `history/` 包裹、无 `edition/` 目录，见[文件结构文档](../../../docs/file-structure.md)。日志与 trash 的持久化（hit 日志段跟随者增量落盘、id 计数器写入文件 meta 续号、跨会话撤销）已落地，见[会话存储内核文档](../../store/docs/store-document.md)。

物理分块是内核的持久化实现细节，分块依据不绑定尝试语义（尝试派生自前端导航，见前端文档）。`TreeBlock` / `AttemptBlock` 现行设计与尝试语义的绑定关系待调整。

# 操作文档

本文档记录 Undo/Redo 体系中操作模型的设计意图与实现语义。

> [!NOTE]
>
> **实现状态**：分子操作记录结构、commit 边界单管线（`HitCommitter` + `BoardApi` 记录化）、三级容器模型（增量式分子 `molId`、超分子 `supraId` 即时物化与 close-supra 聚合折叠、discard 型取消选择）、撤销与重做的运行时语义均已落地（`src/kernel/hit/`）；旧日志形态（`supraOpId` 草稿凝聚）只读兼容。`history/trash/` 当前为内存态（`BoardCore.trash`），持久化与 `move-head` 的应用入口待后续落地。

## 操作层级

操作分三级：

- **原子操作** — 帧增量（amend 流），发生在 AOM 动态图中，不产生 hit 节点、永不落盘，被 endMol 吸收。
- **分子操作** — 一次手势或单步修改凝聚的独立可撤销单元，hit 节点的携带单位，内核共享树的生长单位。
- **超分子操作** — 一次「选择 → 修改 → 提交」会话，多个分子操作的有序组合，撤销与协作的粒度单位。

hit 节点的粒度只有分子操作与超分子操作两种，合称**节点粒度**。

```mermaid
flowchart LR
    subgraph supra["超分子操作"]
        direction TB
        m1["分子操作"] --> m2["分子操作"] --> m3["分子操作"]
    end
    atom["原子操作 × N<br/>"] -- "endMol 凝聚" --> m1
```

## 原子操作

原子操作多为采样点级别：书写时的采样点追加、拖拽中的帧位移等瞬时变化。原子操作发生在 AOM 动态图中，不进 hit、永不落盘；进行中经 amend 事件流（begin-mol / amend / end-mol / abort-mol）向远端 volatile 广播（只画不存），同一逻辑操作的全部原子操作在 endMol 时被吸收、凝聚为分子记录上链——单手势操作在手势结束时 endMol，多手势操作（多手势的对象创建、修改）在最终提交时凝聚。

## 分子操作

分子操作按**作用对象**分为两类：

- **对象级操作**： 改变白板内容或对象的图层归属
- **树级操作**： 改变 hit 自身

分子操作按**对 hit 的作用**分为四类：

- **增加节点类**： 在 HEAD 之后追加节点：增加对象、修改对象、删除对象、选择对象、取消选择对象
- **移动指针类**： 更改 HEAD 指针、重做
- **改挂类**： 撤销：在目标节点的父节点处分叉并改挂后续链；目标为活动链末端时退化为纯 HEAD 回退
- **折叠类**： 闭合超分子（close-supra）：把活动链上同 supraId 的连续节点段折叠为聚合节点，自身不产生节点

分子操作按**作用域**分两组：

- **作用在白板上**：增加、修改、删除、选择、取消选择对象——效果落在白板文档状态上，可被撤消操作抵消。
- **作用在时间回溯树上**：撤销、重做、更改 HEAD 指针、闭合超分子——效果落在树的结构与指针上；撤销与重做经树的结构与指针变化抵消或恢复白板操作的效果，白板状态随投影联动。

分子操作有两种物化形态：

- **增量式分子**：以 `beginMol → amendMol → endMol/abortMol` 生命周期承载一次手势；开启时分配 molId，进行中只产生 amend 流（原子，永不落盘），`endMol` 物化为分子记录（每对象一条、同 molId），`abortMol` 丢弃 amend 流不留痕。同 molId 且同 supraId 的相邻记录在树上归并为一个分子节点。
- **即时式分子**：无生命周期，提交即物化上链（无 molId），与旧日志形态一致；选择、取消选择等单步操作为此形态。

### 操作无法撤消

日志只增不删，任何操作一经记录永久留在日志中。撤消操作撤消的是目标操作在白板上的效果——效果由新操作抵消，原操作仍在日志中、可溯源。树操作中：撤销的效果由重做抵消，更改 HEAD 指针可再次移动。

节点注解（标记关键点、注释节点）归 UI 层，不进 hit。

### 分子操作的记录

记录的公共字段：

- `id`：操作 id，形如 `"{source}/op-{n}"`，复用 id 命名空间（见[时间回溯树内核文档](undo-tree-kernel-document.md)）。
- `type`：操作类型（九类：八类分子操作 + 闭合超分子记录，见下）。
- `source`：发起者标识，即 hit 节点的 author。
- `time`：毫秒物理时间标记；全序按（时间, author）时钟环决胜，同 author 再按操作序号决胜。
- `parentId`：创建时本地视角的父节点 id（根为 `null`）；建树以时间序为准。
- `supraOpId`：旧日志形态（K1.5 草稿凝聚）的超分子关联（首分子自指），只读兼容；三级容器模型的新记录不写，恒为 `null`。
- `molId`：增量式分子 id，形如 `"{source}/mol-{n}"`；仅增量式分子的增加/修改对象记录携带，即时式分子为 `null`。
- `supraId`：归属超分子 id，形如 `"{source}/supra-{n}"`；独立分子为 `null`；仅增加节点类操作可携带。
- `discard`：放弃型闭合标志，仅取消选择有意义：`true` 表示放弃修改、回选择前快照（载荷携带 `restore` 还原点）；缺省 `false`。
- `properties`：涉及属性的集合（如 `position`、`property`、`data.points`），冲突合并的判定粒度。
- `payload`：类型载荷（形状见各操作）。

快照与层栈：修改前后快照——undo 用前快照回退，协作用后快照传播；删除的对象移入 `history/trash/`，代替后快照。层栈快照——操作时刻的完整 z-order（增加与修改对象记录），撤销与层位修复的定位依据：快照内成员按相对位置定位，快照外的层按时间序判定上下，后到者居上。

三个原则：

- **分子操作的边界是提交的效果**：单手势操作（一笔画线、一次拖动）以增量式分子承载——beginMol 开启、手势帧走 amend 流、endMol 物化凝聚；多手势操作（多手势的对象创建、对象修改）的中间手势只产生原子操作，最终提交时才凝聚。Core 侧入口已收口（`BoardApi.eraseData`、AOM `apply`），在单点按提交时机包装。
- **不跨端重放操作语义**：同步复制的是效果（快照），各端直接应用快照，免除跨端重放操作语义（如切割几何）的逐字节一致性要求。
- **操作为王**：操作是一等记录（id、author、时间、内容），可产生多个节点；树是日志的追溯结构，节点数据放在数据池中凭 id 获取。移动指针类操作不产生节点，也可入日志。

### 增加对象

向静态图添加某对象。记录区块 id、对象 id、对象全量内容，以及操作时刻的完整层栈快照（z-order），用于撤销与层位修复时恢复层位关系。

载荷：`{ chunkId, objectId, data, layerStackSnapshot }`——`data` 为对象全量内容（可 JSON 序列化，`deserialize` 可重建实例）。

### 修改对象

修改某对象的属性、数据或层位关系。记录区块 id、对象 id、涉及属性集合、修改前后快照，以及操作时刻的完整层栈快照。z-order 调整（置顶、置底、上移、下移）视为修改对象，层位变化经层栈快照表达。

载荷：`{ chunkId, objectId, before, after, layerStackSnapshot }`——`before`/`after` 为修改前后的全量快照；涉及属性集合承载在记录的 `properties` 字段。

### 删除对象

从静态图删除某对象。记录区块 id 与对象 id，对象移入 `history/trash/`。

载荷：`{ chunkId, objectId }`——对象本体由 commit 边界移入 `history/trash/`，记录只携带定位信息；撤销删除时按 trash 中的本体与层位边恢复。

### 选择对象

将对象选入 AOM。选择改变对象的图层归属，该操作可能进入 hit 内核；更多以超分子操作中的分子呈现，鲜有单独出现。

载荷：`{ chunkId, objectId }`。

### 取消选择

将对象移出 AOM（提交回静态图，或放弃更改）。与选择对象配对：选择把对象提升到输出层，取消选择将其交回，图层归属变化是双向的。同样更多以超分子操作中的分子呈现（如拖拽 = 选择 + 修改 + 取消选择）。

放弃型闭合（discard）：记录的 `discard` 为 `true` 时表示放弃更改——对象退出活动层，状态回选择前快照（Esc 闭合路径，零撤销动作）；载荷携带 `restore` 选择前快照，重放/重做/远端凭以还原实例。

载荷：`{ chunkId, objectId, restore? }`——`restore` 仅 discard 型闭合携带。

### 更改当前 HEAD 指针

HEAD 指向当前状态对应的节点。按「所有用户一致」原则：网络同步良好时，所有用户的 HEAD 指针相同，每个用户的 hit 也相同。因此更改 HEAD 是分子操作，记录在树中并同步到各用户。更改 HEAD 的用途：撤销与重做的指针效果、移动至其它分支。

载荷：`{ targetNodeId }`。

### 撤销

撤消操作 D 在白板上的效果，D 缺省为本端来源最近的活动链节点（各撤各的），可显式指定。撤销本身也记录于日志——操作无法撤消，撤销抵消的是效果，D 本身仍留在日志中、可溯源。撤销记录**目标节点**；HEAD 移动是应用时算出的效果。应用规则：

1. 在 D 的父节点处分叉：把 D 与 HEAD 之间的链（不含 D）改挂到分叉点；原位置按 (时间, author) 截断保留——不晚于撤销操作的节点留下共享数据，晚于的只存在于撤消分支。
2. HEAD 移到新末端。
3. D 是活动链末端时，没有可改挂的节点，效果退化为 HEAD 回退到 D 的父节点。
4. D 不在活动链上（已被撤消）时，撤销无效，被吸收。

载荷：`{ targetNodeId, previousHeadId }`——`previousHeadId` 为撤销前的 HEAD 位置（重做的移动目标）。

离线期间的撤销在合并时按合并树上的目标节点位置应用：目标已被推到链中间时，撤销呈现分叉改挂的一般形态，离线意图被保留（见[时间回溯树内核情景推演](undo-tree-kernel-example.md)情景四）。

### 重做

把 HEAD 移到最近一次生效撤销所记录的原 HEAD 位置（撤销前的活动链末端）。原 HEAD 位置所在的分支始终留在树上，重做是纯 HEAD 移动，按条件应用。被吸收（未生效）的撤销不产生重做目标；撤销后活动链上已有新操作时，重做是否可用由 UI 策略决定。

载荷：`{}`——空载荷；移动目标由最近一次生效撤销的记录派生。

### 闭合超分子

超分子会话的闭合信号（close-supra）。树级操作，无白板效果，自身不产生节点、不作为超分子成员（记录顶层的 `supraId` 恒为 `null`，待闭合的超分子 id 只在载荷中）。`endSupra(key)` 在该超分子的成员记录不少于 2 条时追加本记录（单成员超分子的折叠是恒等，不产生记录）；树构建见到本记录时，把活动链上同 supraId 的连续节点段逐段折叠为聚合节点——段内不少于 2 节点才折叠，已撤销分支上的成员不参与，成员被并发异节点分隔时按段分别折叠（退化），重复闭合幂等。

载荷：`{ supraId }`——待闭合的超分子 id。

## 超分子操作

多个分子操作按序合成一个超分子操作，作为整体成为撤销与协作的粒度单位。超分子承载一次「选择 → 修改 → 提交」会话。

例：一次 FD 擦除手势 = 修改对象（回写首段）+ 增加对象（分裂段，可有多个）+ 删除对象（整笔擦没）的顺序组合（见[对象擦除工具文档](../../../ui/devices-dag/tools/eraser/docs/object-eraser-document.md)）。选择对象更多作为超分子操作中的分子出现。

实现语义（已落地）：

- **指定式归属（supra key）**：超分子按键开启与闭合（`beginSupra(key)` / `endSupra(key)` / `abortSupra(key)`，谁开启谁关闭）；开启时分配超分子 id（`"{source}/supra-{n}"`）。分子操作显式指定自己要进入的超分子（效果摘要携带 `supraKey`，可跨通道序列化），未指定的提交永远独立成录、不受开启中的超分子影响——工具组合以会话 key 汇聚一次「选择 → 修改 → 提交」（如 handoff wrapper），无 key 的并发工作（如同时绘制新笔画）不会被吞入。
- **即时物化**：开启期间成员提交即时物化上链（记录携带 `supraId`），不缓冲草稿；成员在日志与树上各自独立有效。`endSupra(key)` 先强制闭合其下未闭合的增量式分子（endMol 物化），再按上节规则追加闭合超分子记录，触发聚合折叠。
- **异常中止**：`abortSupra(key)` 撤销全部活跃成员（已物化成员逐个撤销，在途分子 abortMol），取消不留净效果。
- **撤销粒度**：未闭合的超分子内 undo 落最近本端分子（分子级）；闭合后 undo 撤整个聚合节点。拖动中 undo 先把本端未闭合分子强制 endMol 物化再撤（`BoardApi.undo` 返回 `forcedEndMolIds`），保证所有效果都有记录可撤。Esc 闭合走 discard 型取消选择（restore 快照回选择前，零撤销动作）；undo 聚合节点时 commit 与 discard 殊途同归（回选择前、取消选择）。
- **旧形态兼容**：旧日志形态（`supraOpId` 草稿凝聚）只读兼容——重建时成员组凝聚为单节点，与新形态记录在同一棵树收敛（见[时间回溯树内核文档](undo-tree-kernel-document.md)）。
